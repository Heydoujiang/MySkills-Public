# DCC 制作、工程修订与拍屏

## 软件选择

用户指定 DCC 时按用户要求。否则运行 `scripts/workflow.py discover`，按 Maya、3ds Max、Blender、其他 DCC 顺序检查候选。对选中的软件实际检查启动、许可、源格式导入与骨骼 FBX 导出；不可用再检查下一项，全部不可用才询问。不要为此扫描整个磁盘或自动下载软件。

随附发现/启动探针内置 Maya、3ds Max、Blender、Houdini；这不是所有 DCC 的穷举。若均不可用，继续检查本地安装记录和用户给定目录中的其他 DCC，按其本地脚本接口验证，不能因内置探针未命中就直接声称没有软件。

随附 Maya 后端由 mayapy 运行，支持 `.ma/.mb/.fbx/.obj`。Max/Blender/其他软件需用其原生脚本实现同样的刚性绑定、动画、采样和预览契约；不能把 Maya 脚本直接交给它们。不要因为缺少 Blender 渲染器而判定 Maya 不可用。

## 工程与备份

首次导入前保留原始文件，创建一个动画工作工程并记录绝对路径。之后的用户修改都在该工作工程继续：

1. 先把当前已保存工程及对应动画配置复制到带时间和版本标识的备份目录，核对备份完整性；已有备份不覆盖。
2. 如有未保存修改，通过可用 DCC API 保存当前状态后备份；无法确认时说明情况，不能直接重开文件丢掉用户改动。
3. 在原工作工程更新关键帧/配置并保存到同一路径。只重建本流程拥有的动画节点，保留用户添加的相机、材质与其他编辑；不能把“修改工程”实现成每次从静态源重新生成整个场景。
4. 重新拍屏、记录哈希，旧确认失效。回退时从备份恢复主工作工程，不能悄悄切换到备份路径继续制作。

记录 `dccScene` 指向实际主工程；备份、导出副本和高面数清理副本均不是新的主工程。

## 动画设计与导出

检查单位（UE 目标 cm）、负/非均匀缩放、层级、材质、重名和独立网格变换。源场景禁用脚本节点执行。每个运动零件对应一根骨骼，全部顶点权重 1；保存稳定 partId、骨骼名、分组、方向、偏移、旋转、起止时间及源哈希。

有参考视频先观察并拆解其动作顺序、分组、加减速和重叠；不把镜头运动误作零件运动。没有参考时，局部小件轻快引导，主体按结构分层错峰衔接，动作窗口适度重叠，缓起缓停；避免小件完全停止后主体突然集中启动。基于结构设计拆出方向和留白，不按统一径向位移生搬。

时长由节奏和可读性决定。本次 5.5 秒是已确认样例，不是所有物件默认必须遵循的时长。Maya 模板使用 30 fps，其他帧率需联动导出、采样和验证。空间配置生成器只提供可编辑初稿，不保证真实工艺顺序或绝无穿插。

只导出装配→展开的 FBX 2018 和对应验证样本。回装在 UE 反向取样；预览即使包含停留/回装，也不能把往返整个片段映射为 Progress 0–1。模型变化时重新检查映射，不以更新哈希掩盖旧配置不匹配。

## 原生拍屏优先

在制作 DCC 中使用原生视口拍屏，单个固定视角覆盖装配、过渡和最大展开。保持主体清晰、不过度留白、不切模型；预览视角不绑定 UE 的运行摄像机。

- Maya：优先 `playblast`，用脚本创建/指定原生视口和相机，优先离屏输出。此路线已实测。
- 3ds Max：优先原生 Create Preview/视口预览，通过本地支持的 MAXScript/API 自动化。实际编码器与无窗口能力需检查，尚未在此流程实测。
- Blender：优先原生视口动画预览（Viewport Render Animation），先检查当前显示上下文和编码能力，不能假设任意 `--background` 环境都可运行 OpenGL 视口拍屏。尚未在此流程实测。
- 其他 DCC：选择同类原生视口预览；必要时适配本地 API。

原生能直接生成大小合理的压缩视频时直接交付。Maya 未压缩 AVI 过大时保留 AVI、快速压缩 H.264 MP4：优先可用硬件编码，失败时回退软件编码；核对完整解码、帧数、帧率、尺寸及画面质量。不要默认增加离线渲染、图片序列和重复编码。硬件编码不是运行该 Skill 的必需硬件条件。

旧 `render_preview.py` / `render_animation_preview.py` 是后备渲染工具；仅在用户明确要求更高画质或原生拍屏确实不可用且替代方案已说明时使用，不作为常规必经步骤。

## 确认记录

先检查完整视频并向用户展示。获得对该版本的真实认可后记录 `status=approved`、`userConfirmation`、`fbxSha256`、`dccSceneSha256`、`previewSha256`。兼容旧记录中的 `mayaFileSha256`，新 DCC 用通用字段。用 `workflow.py check-approval` 核验；不能伪造确认或因无回复自动通过。

缩略图使用该已确认动画在 Progress=1 的真实视口图或渲染图，并导入 UE Texture2D；不能用生成式图片编造零件结构。三角面级无穿插、真实拆卸工艺不是盒体检查能证明的，按实际验收范围说明。
